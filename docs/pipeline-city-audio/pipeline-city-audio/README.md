# Pipeline City: audio handoff (SFX, UI, ambience, music)

This folder is everything needed to add sound to Pipeline City in its repo (`main` at `da577448`): every gameplay sound effect, every menu and HUD UI sound, two ambience loops, the reactive Afterglow music (direction **B**, approved by Khalil 2026-11-21), the mix contract, and the code plan.

You need only the repo and this folder. It is written to be implemented by Khalil with Claude Code.

## Scope
- **In:** 353 Ogg Vorbis files (48 kHz): gameplay SFX (153: pitched cues at 4 render roots, a level-up stinger in all 12 keys, unpitched cues once), UI (26 with round-robin variants), ambience (2 seamless loops), and the Afterglow music (172: 6 loop layers in all 12 keys, a menu loop, chromatic music notes, level-up and fault stingers per key). A Web Audio engine design for TS / Vite / Preact / three.js with code, an event-to-sound map keyed on real repo names, a mix tokens file, previews and measured checks.
- **Out:** no gameplay changes; no repo changes were made; no UI redesign. One proposed UI addition (audio sliders in Settings → Interface) needs Art Director sign-off (KNOWN-ISSUES §1).
- **Status:** synthesized and measured; not yet heard by a person, not yet run in any browser (KNOWN-ISSUES §2–3).

## Listen first
1. `previews/sfx_preview.ogg`: 30 s game moment (build, boot, jobs, payouts, faults, level-up, pause). Cue list: `previews/sfx_preview_cues.md`.
2. `previews/ui_preview.ogg`: 21 s of menus (hover, tabs, sliders, toggles, confirm, typing, toasts, pause menu). Cue list: `previews/ui_preview_cues.md`.
3. `previews/music_reactive_preview.ogg`: 40 s of the Afterglow music reacting to play, a level-up and a pause. Cue list: `previews/music_reactive_preview_cues.md`.

## Reading order
1. `README.md` (this file).
2. `SPEC.md`: what plays when. §1 decisions, §3 the full event-to-sound map, §4 UI by screen (matches the AD menu handoff), §5 ambience, §6 music, §7 mix and levels, §8 key transposition.
3. `IMPLEMENTATION.md`: the audio graph, loading, the cue API, event wiring, ambience, the music director (`stitchLoop`, current + next key), pause, hidden tab, sliders, with TypeScript; then a PR order.
4. `mix-tokens.json` / `mix-tokens.ts`: every number (bus levels, ducking, fades, rate limits, log rules, transpose rule). Code reads these; do not hard-code.
5. `assets/manifest.json`: every file, its target repo path (`public/audio/...`), cue id, root or variant, length and measured loudness.
6. `ACCEPTANCE.md`: checks you can run (`python3 sources/check_refs.py` proves the docs and assets agree).
7. `KNOWN-ISSUES.md`: gaps and open points.

## Precedence
`mix-tokens.json` wins over numbers in the prose. SPEC wins over the previews. The previews are illustrations (the SFX reel's quiet pad is a stand-in; the music preview is the real music).

## Re-render
The generators still write Ogg files to `assets/<category>/` in this folder. After a render, copy the changed files to `public/audio/<category>/` in the repo (the repo copies are the shipped ones), then run `sources/check_refs.py`.
```
python3 -m venv .venv && .venv/bin/pip install numpy scipy matplotlib soundfile
cd sources
../.venv/bin/python gen_sfx.py && ../.venv/bin/python gen_ui.py && ../.venv/bin/python gen_ambience.py
../.venv/bin/python check_all.py && ../.venv/bin/python build_manifest.py
../.venv/bin/python gen_previews.py && ../.venv/bin/python plot_previews.py
```
ffmpeg with libvorbis must be on PATH. Synthesis is deterministic (fixed seeds). Music: see `sources/music/README.md` (copy `sources/music/` to `<dir>/sources/` first; KNOWN-ISSUES §13).
