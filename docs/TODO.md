# TODO

Source of truth for tasks in this repository.

## Rules for every task

- One task = one commit, touching only the paths listed in `Files`. Stage with `git add <paths>`, never `git add -A`.
- `npm test` and `npm run build` must both pass before the commit. If they cannot, change nothing and say why in one line.
- Read the task's `Docs`, not the whole repo.
- UI code: every size is relative (rem, em, %, clamp). `src/core/ui/scaling.test.ts` must stay green.
- Use the Edit tool, never rewrite a file from a script.
- When done, delete the task's line.

## Tags

- `[auto]` an unattended session can finish and verify it with tests and the build.
- `[owner]` needs a decision from the owner first. Never run unattended.
- `[~]` instead of `[ ]`: waiting on the owner.

Line format (the script matches `^- \[ \] <ID> `): `- [ ] ID [tag] Title. Files: ... Docs: ... Done when: ...`

## Phone performance (bench of 2026-11-09)

Target: a high-end phone. Priority by screen: P1 main menu, P2 gallery, P3 Build my PC. Measure with `npm run bench:modes -- out.json --phone` (412x915 at dpr 2.6, CPU slowed 4x, Low and High; it counts draw calls, triangles and pixels per WebGL context) and `npm run bench:3d -- out.json --size 412x915 --dpr 2.6 --preset Low` (the game: per-pass CPU and GPU time). A desktop GPU hides the phone GPU's cost: read draw calls and triangles as GPU load, frame time as CPU load. The 4x slowdown is an estimate; the owner's phone run is task PERF9.
Findings (phone profile, Low, CPU/4): menu 31 fps (p50 28 ms); gallery 18 fps; Build my PC 5 fps (p50 155 ms, 10 s of long tasks in 2.5 s). The room draws 1.16 M triangles from 2065 meshes, 1224 materials and 1711 shadow casters; its scene pass is CPU bound (7 ms CPU vs 1.3 ms GPU on a desktop). It keeps drawing behind Gallery and Build my PC (3.2 M of the 3.7 M triangles in Gallery, 3.4-4.1 M of 5.8 M in Build my PC). Zoomed in on the CPU die the game costs 0.3 M triangles and 2.7 ms: the zoomed-out room and board views are the cost. Presets barely change CPU time (Low vs High: room idle 7.5 vs 7.0 ms). Tag `[look: x]` = the task can change the picture (none, low, medium, high). Open owner questions: PERF4 (30 fps in the menu), PERF8 (auto-adjust on phones). Done already: first start on a touch device (`pointer: coarse` and no hover) gets Low at 0.75 scale and 30 fps (`deviceDefaults`, `src/app/graphics.ts`).
Order: highest yield first.
