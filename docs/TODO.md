## Rules for every task

- One task = one commit, touching only the paths listed in `Files`. Stage with `git add <paths>`, never `git add -A`.
- Run the tests you touched and `npm run typecheck`. Run `npm run test:q` and `npm run build` before a push. If they cannot pass, change nothing and say why in one line.
- Read the task's `Docs`, not the whole repo.
- UI code: every size is relative (rem, em, %, clamp). `src/core/ui/scaling.test.ts` must stay green.
- Use the Edit tool, never rewrite a file from a script.
- Any task with a look needs a before and after shot (`npm run shot`), and a `--prod` shot before a push.
- When done, delete the task's line. If a task is only part done, rewrite its `State` and keep it.

## How to read a task

## Where things stand (2026-11-17, branch `main`)

Assessment, read from code (nothing measured yet):

1. **Every step rebuilds the whole machine.** `BuildStage.rebuild()` (`buildmode3d.ts:225`) removes and disposes the `Machine3D`, then builds a new one from a fresh snapshot. `takeOut`, `putBack`, `fit`, `plugNeeded`, `fitShell` and the end of every job call it. Taking out a part behind others (a RAM stick behind a cooler, a GPU) takes out its blockers, then puts each back: one swap is about 2 rebuilds per touched node, plus 1 for the job end. Each rebuild disposes geometry and materials that the next build recreates; at Low, `shareMaterials` makes the disposed material a program relink risk (`docs/render/three.md`, "Merges").
2. **A part's motion is a plain slide.** `buildmotion.ts` has keyframes of offset and one turn about z (`poseAt`, smoothstep ease). Every `hold` key (latch, screw, lever) leaves the part at home: only the text changes. Nothing in the 3D model moves for a latch, a screw or a load lever. The cables that feed the part do not follow it (they are unplugged first, by graph order, so this is only a gap in the story, not a bug).
3. **A cable comes out as a sliding group.** `takeOut` for a cable node plays the `cable` motion: the whole cable object moves 260 then 2600 units up +z (`CABLE` in `buildmotion.ts`), then `disconnectCable`, then `rebuild()`. The strands do not stretch or bend, the plug does not turn, the strand ends leave their grommets with the group, and the cable then reappears loose. `putBack` is the same motion backwards after a rebuild. The real mechanism already exists: `PlugHand` (`plughand3d.ts`) pulls a plug along its socket axis with `pullOffset`, pops it at `POP_PX`, holds it with a rope sim (`Rope`, strands keep their length, fixed at the grommets), and slides it in with `insertOffset`. Only a pointer drives it today (the room and the stage's own drag).
4. **Seat and settle exist and are fine.** A part going in dips 0.3 s past its seat then settles (`step`, `SETTLE_*`). Keep it.

Order of work: ANIM-01 (measure), ANIM-04 (cables, independent), ANIM-02 and ANIM-03 (swap cost), ANIM-05 (part motion), ANIM-06 (docs and bench in CI).
