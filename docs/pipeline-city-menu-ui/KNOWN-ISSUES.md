# Known issues and open points

1. **Old "P" mark on the in-scene monitor.** The Build machine's monitor and the room monitor still show the old "P" mark and the "PIPELINE CITY" boot picture. Its texture should move to the new wordmark and strip. Asset work, outside this handoff; do not draw it in the UI.
2. **Grey baked into `full.webp`.** `public/stills/builds/full.webp` (320 × 240) has a grey floor baked in, so it shows as a grey box on dark backgrounds. Do not use it on a UI surface until it is re-exported transparent at 2×. The phone Build in r3 uses the live 3D stage instead, so nothing in this spec needs it.
3. **No High or Ultra captures.** All captured frames are at the Low or Medium preset. The mocks do not show how High or Ultra look under the tabs and ramps; the contrast numbers for in-game surfaces are computed over pure white, so they hold for any frame.
4. **No phone room frame for Gallery or Build.** There is no captured phone frame of the Gallery or Build scenes. The phone mocks and renders use the flat studio colour (Gallery) or a crop of the desktop Build capture. Frame them with the live camera and check the coverage on a real phone size.
5. **The Build capture is a simulated crop.** `reference/renders-r3/07-*` and the v3 Build mocks use the v2 capture scaled 1.15× (desktop: image 2208 × 1242 placed at −218, 14) to stand in for the reframed camera. The real reframe (IMPLEMENTATION.md step 7) must reach the machine box x 375 to 1446, y 140 to 898; the exact look comes from the camera, not from the mock.
6. **Level bar wording.** The r3 renders show "0 / 3 goals" with 3 cells. The code has no goal list; it has client base and the next threshold (`levelBar()`: `label` "0 / 3", `pct`). SPEC §5.12 maps it: cells = the threshold (at most 10), filled to `pct`, text "0 / 3 clients". Resolved: the v3 desktop mocks now say "0 / 3 clients".
7. **Gallery stills are small.** The case stills in the mocks are 480 px wide. In the game the Gallery shows the live 3D part, so this only affects the mocks' sharpness.
8. **Out-of-scope panels keep their old look.** Shop, Almanac, Log, OS, Trace, Stats, the level-up popup and the part picker card keep the glass and navy look for now. They will look different from the new HUD until a later round.
9. **Line references were corrected.** Earlier notes put the 3D colours at `buildmode3d.ts:152`, `viewer.ts:68` and `viewer.ts:72` with a floor colour `0x1a1d26`. On `main` `7f56e17` they are `buildmode3d.ts:332` (`#0e1118`), `viewer.ts:115` (rim `0x9ab8ff`) and `viewer.ts:121` (floor `0x0c0f18`). A second check found more drift: the Build clear colour call is at `buildmode3d.ts:342`, and the Shift-drag binding is in `src/core/render/three/pad.ts:82`, not `board3d.ts`. IMPLEMENTATION.md uses the checked values. Re-check every line before a PR, since other sessions edit these files.
10. **Two choices made in this spec that Khalil has not seen yet**: Settings and New game opened inside a game use a neutral ramp instead of the navy scrim (SPEC §5.6a), and the Settings slider fill is ink at rest and cyan only when focused (SPEC §5.6). Both follow the approved rules (no navy in game, cyan only on focus).
11. **Responsive behaviour is rule-based.** Only 1920 × 1080 (desktop) and the phone mocks are drawn. The phone reference is 390 × 844. SPEC §6 defines the rest; screenshots at the sizes in ACCEPTANCE.md §4 are the check.
12. **To verify during the work (not yet checked).** Each item below is a claim the package makes without a test:
    - Offline behaviour: the menus and the game load and run with no network; only the NET chip changes.
    - Boot failure: no designed state exists yet (SPEC §5.14 is proposed).
    - Crash panel and Starting screen: keep their current wording; check the surfaces only.
    - NetLensButton gate: the network lens button shows only when its gate (`Inventory.tsx:75`) is open; confirm the gate before the HUD tabs ship.
    - Gallery stills at 480 px: the mock stills are 480 px wide; in-game the part is live 3D, so confirm the Gallery look at 390 × 844 and 1920 × 1080 before relying on stills.
13. **Contrast and glyph coverage are unverified.**
    - Contrast numbers in SPEC §11.1 are computed over pure white. No check was run on the live frame. Any text that fails in review is listed as an exception in SPEC §11.1 before the PR.
    - Glyph coverage: the arrow, square, chevron and infinity glyphs must exist in the five font files in `assets/fonts/` (IBM Plex Sans Condensed SemiBold, Sans Regular, Sans Medium, Sans SemiBold, Mono Medium). A glyph missing from a file falls back to the next font and breaks the look. Check each glyph in the browser's rendered-fonts panel.
